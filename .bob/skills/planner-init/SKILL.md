# Planner Init

Bootstrap the project planner: verify tooling, interview the user, and write `docs/planner.yaml`.

Run this skill **once per project** before using any other `/planner-*` skill.
It is safe to re-run — it will show the existing config and offer to update it.

---

## Phase 0 — Check Existing Configuration

```
glob: docs/planner.yaml
```

**If `docs/planner.yaml` exists:**
- Read the file and display the current configuration to the user.
- Ask:

  ```
  ask_followup_question: "A planner configuration already exists. What would you like to do?"
  suggestion_a: "Update the configuration (change milestone duration, versioning, etc.)"
  suggestion_b: "Leave it as-is and exit"
  ```

  If the user chooses to leave it, stop here.

**If not found:** proceed through all phases.

---

## Phase 1 — Verify Tooling

### Step 1.1 — Check gh CLI

```
execute_command: gh --version
```

**If the command fails:**
- Stop and tell the user:
  _"The GitHub CLI (`gh`) is not installed or not in PATH. Please install it from
  https://cli.github.com and authenticate with `gh auth login`, then re-run `/planner-init`."_
- Do not proceed further.

### Step 1.2 — Check gh authentication

```
execute_command: gh auth status
```

**If not authenticated:**
- Stop and tell the user:
  _"The GitHub CLI is installed but not authenticated. Run `gh auth login` first, then
  re-run `/planner-init`."_
- Do not proceed further.

### Step 1.3 — Detect repository

```
execute_command: gh repo view --json nameWithOwner --jq .nameWithOwner
```

Extract the `owner/repo` string (e.g. `sasadangelo/fasturl`). This becomes the `repo` field
in `planner.yaml`.

**If the command fails** (not a GitHub repo or no remote):
- Ask the user to provide the repo slug manually: `"owner/repo-name"`.

---

## Phase 2 — Interview

Ask these questions in sequence. Use `ask_followup_question` for each.

### Q1 — Milestone duration

```
ask_followup_question: "How long should each milestone (development cycle) be?"
suggestion_a: "2 weeks"
suggestion_b: "4 weeks"
suggestion_c: "6 weeks"
suggestion_d: "I'll set a custom duration in weeks"
```

### Q2 — Starting version

```
ask_followup_question: "What is the starting version for this project?"
suggestion_a: "0.1.0 — first MVP (pre-GA)"
suggestion_b: "1.0.0 — already at GA"
suggestion_c: "I'll enter a custom version"
```

### Q3 — Default issue labels to create

Inform the user that the following labels will be created on GitHub if they do not exist:

| Label | Colour | Purpose |
|---|---|---|
| `backlog` | `#c2e0c6` | Issue is in the backlog, not yet assigned to a milestone |
| `epic` | `#7057ff` | Parent issue grouping related features |
| `priority: high` | `#e11d48` | Must be in the next milestone |
| `priority: medium` | `#f97316` | Should be in the next milestone |
| `priority: low` | `#6b7280` | Nice to have |
| `type: feature` | `#0075ca` | New functionality |
| `type: bug` | `#d73a4a` | Something is broken |
| `type: performance` | `#e4e669` | Performance improvement or benchmark |
| `type: infrastructure` | `#bfd4f2` | CI/CD, tooling, dependencies |
| `type: docs` | `#cfd3d7` | Documentation only |

```
ask_followup_question: "Should I create these labels on GitHub now?"
suggestion_a: "Yes — create all labels"
suggestion_b: "Skip — I'll manage labels manually"
```

---

## Phase 3 — Write `docs/planner.yaml`

**If the file does not exist:** create it with `write_file`.
**If it exists:** patch only changed fields with `apply_diff`.

```yaml
# Project planner configuration
# Generated by /planner-init — edit manually or re-run /planner-init to update.

repo: "<owner/repo>"
milestone_duration_weeks: <n>
versioning:
  current: "<x.y.z>"
  # Increment rules:
  #   patch (z): bugfix only
  #   minor (y): each milestone / MVP
  #   major (x): GA release (0.x.0 → 1.0.0) or breaking change post-GA
```

---

## Phase 4 — Create GitHub Labels (if approved)

For each label in the table above, check if it already exists and create only the missing ones:

```
execute_command: gh label list --json name --jq '.[].name'
```

For each missing label:

```
execute_command: gh label create "<name>" --color "<hex>" --description "<purpose>" --force
```

---

## Phase 5 — Report

Tell the user:
- `docs/planner.yaml` written ✓
- Labels created (list) ✓
- Next step: _"Run `/planner-backlog` to generate the product backlog from your project documents."_
